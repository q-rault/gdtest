## 1. Install the CLI

Via Cargo:

```sh
cargo install gdtest
```

Requires Rust 1.85+.

Or download a binary from the [GitHub releases page](https://github.com/q-rault/gdtest/releases):

| Platform | Archive |
| --- | --- |
| macOS arm64 | `gdtest-*-aarch64-apple-darwin.tar.gz` |
| macOS x86_64 | `gdtest-*-x86_64-apple-darwin.tar.gz` |
| Linux x86_64 | `gdtest-*-x86_64-unknown-linux-gnu.tar.gz` |
| Windows x86_64 | `gdtest-*-x86_64-pc-windows-msvc.zip` |

Put the `gdtest` binary on your `PATH`.

If you do not want to put it on `PATH`, the Godot editor plugin can still use
`GDTEST_BIN=/path/to/gdtest`.

## 2. Set the Godot executable (if needed)

gdtest first tries explicit configuration. If nothing is set, it falls back to best-effort auto-discovery across common command names and common install locations.

1. `--godot-exe` CLI flag
2. `GODOT_EXE` environment variable
3. `GODOT_EXE` in a `.env` file at your project root
4. `godot_exe` key in `gdtest.toml`

If your binary is named differently (e.g. `godot4`) or is not on `PATH`, set it in any of the above locations:

```toml
# gdtest.toml
godot_exe = "godot4"
```

```sh
# .env (auto-loaded by gdtest from the project root)
GODOT_EXE=/Applications/Godot.app/Contents/MacOS/Godot
```

## 3. Initialize the project

Run this from your Godot project root:

```sh
gdtest init
```

This installs `addons/gdtest/` into the project:

```text
your-project/
`-- addons/
    `-- gdtest/
        |-- gdtest_worker.gd
        |-- gdt.gd
        `-- gd_test.gd
```

The runtime addon is also included in each release archive.

## 4. Editor integrations

Godot editor plugin:

1. `gdtest init` installs it by default.
2. Enable **gdtest Editor** in Project -> Project Settings -> Plugins.
3. The panel resolves the gdtest binary in this order:
   - `GDTEST_BIN`
   - nearby project-local binaries
   - `gdtest` on `PATH`

If you only want the runtime harness:

```sh
gdtest init --no-editor
```

VS Code:

```sh
code --install-extension vscode-gdtest-*.vsix
```

Optional settings:

```json
{
  "gdtest.executablePath": "gdtest",
  "gdtest.testDirectory": "test/"
}
```

Zed:

1. Download `extension.wasm` from a release.
2. Put it next to `extension.toml` and `tasks.json` from `zed-gdtest/`.
3. Place the folder in your Zed extensions directory.

- macOS / Linux: `~/.config/zed/extensions/gdtest/`
- Windows: `%APPDATA%\\Zed\\extensions\\gdtest\\`

## Compatibility

| CLI version | Required harness (`addons/gdtest/`) | Supported Godot |
| --- | --- | --- |
| 0.2.x | 0.2.x | 4.6, 4.7 (tested) |

The addon and CLI are versioned together and released in the same archive. If you mix versions, gdtest will print a clear error at startup pointing to this table.

You can always check which harness version is installed by looking for `HARNESS_VERSION` at the top of `addons/gdtest/gdtest_worker.gd`.

## Verify

```sh
gdtest --version
gdtest test/
```
