## Synopsis

```sh
gdtest                               # scan cwd using discovery patterns
gdtest <target>... [options]
gdtest init [--no-editor] [--force]
gdtest res://test/foo.gd::test_bar   # single test, short-circuits pool
```

A `<target>` is one of:
- `path/to/file.gd` — run every `test_*` in the file
- `path/to/dir` — walk the directory using discovery patterns
- `res://path/to/file.gd` — same, with project-relative prefix
- `file.gd::test_bar` — run exactly that one test function (`::` separates the file path from the function name; no worker pool is created, so you get full stderr output directly)

**Discovery patterns** (configurable via `gdtest.toml`):
- `test/**/*.gd` — any `.gd` file inside a `test/` directory
- `**/*.test.gd` — co-located test files anywhere in the project

## Options

Each option can be set three ways: as a CLI flag, an environment variable, or a
`gdtest.toml` key — whichever is most convenient for your workflow.

| Flag | Env var | Default | Description |
|---|---|---|---|
| `-j, --jobs <N>` | `GDTEST_JOBS` | CPU count | Parallel worker count |
| `--reporter <KIND>` | `GDTEST_REPORTER` | `pretty` | `pretty` \| `tap` \| `junit` |
| `--isolation <MODE>` | `GDTEST_ISOLATION` | `file` | `file` \| `test` (see below) |
| `--filter <REGEX>` | — | — | Only run tests matching regex on `file :: func` |
| `--list` | — | — | Print discovered tests and exit |
| `--timeout <MS>` | `GDTEST_TIMEOUT` | `5000` | Per-test timeout in ms; exceeding it reports an error |
| `--timeout-warn <MS>` | `GDTEST_TIMEOUT_WARN` | — | Slow-test warning (no kill) |
| `--fail-fast` | `GDTEST_FAIL_FAST` | off | Stop after first failure or error |
| `--retries <N>` | `GDTEST_RETRIES` | `0` | Re-run failing tests up to N extra times |
| `--update-snapshots` | `GDTEST_UPDATE_SNAPSHOTS` | off | Rewrite snapshot files |
| `--partition <SPEC>` | — | — | Shard the suite (see below) |
| `--profile <NAME>` | — | — | Activate a `[profile.NAME]` block from `gdtest.toml` |
| `--watch` | — | off | Re-run on `.gd` file changes; Ctrl-C to exit |
| `--no-auto-import` | — | off | Skip one-shot `godot --import` on startup |
| `--godot-exe <PATH>` | `GODOT_EXE` | auto-discovered | Godot binary path |
| `--project-path <DIR>` | — | `.` | Godot project root |
| `--harness <PATH>` | `GDTEST_HARNESS` | `addons/gdtest/gdtest_worker.gd` | Path to worker script |

## Reporters

**`pretty`** (default) — coloured human-readable output with a spinner and summary line.

**`tap`** — TAP v14 format; compatible with `tap-junit`, `tap-parser`, and most CI TAP consumers.

**`junit`** — JUnit XML to stdout. Pipe to a file for GitHub Actions / GitLab CI test reports.

```sh
gdtest test/ --reporter junit > results.xml
```

## Isolation modes

**`file`** (default) — one Godot process per test file. Fast; tests in the same
file share an autoload environment.

**`test`** — one Godot process per test function. ~200 ms startup overhead per
test, but each test gets a completely clean process. Required when tests mutate
global singletons (`GameClock`, etc.) and those mutations leak between tests.

## Partitioning (CI sharding)

Split the suite across multiple CI jobs with `--partition`:

```sh
# Round-robin: each job gets every 3rd test
gdtest test/ --partition count:1/3   # job 1
gdtest test/ --partition count:2/3   # job 2
gdtest test/ --partition count:3/3   # job 3

# Hash-based: stable — same test always lands on the same shard
gdtest test/ --partition hash:1/3
```

`count:N/M` — takes every M-th test starting at position N−1.
`hash:N/M` — FNV-1a hash of `script::func`; distribution is stable across suite changes.

## Watch mode

```sh
gdtest test/ --watch   # re-runs on .gd file change; Ctrl-C to exit
```

## Project init

```sh
gdtest init
gdtest init --no-editor
gdtest init --project-path /path/to/game
gdtest init --no-editor --force
```

`gdtest init` installs the bundled `addons/gdtest/` runtime and
`addons/gdtest_editor/` into the target Godot project by default. Pass
`--no-editor` to install only the runtime.

If a target file already exists with different contents, `init` stops rather
than overwriting local changes. Use `--force` only when you want to replace the
project copy with the version bundled in the current `gdtest` binary.


## Single-test mode

```sh
gdtest res://test/test_player.gd::test_jump   # bypasses pool; full stderr visible
```
