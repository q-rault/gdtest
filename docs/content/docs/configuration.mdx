## Where settings live

gdtest reads its settings from one of two places, with the same keys:

- the `[test]` section of `gdsuite.toml`, for a project that uses
  [gdsuite](https://github.com/q-rault/gdsuite) and keeps every tool's settings
  in one file;
- `gdtest.toml`, for a project that uses gdtest alone.

Place the file at your Godot project root (next to `project.godot`). gdtest
looks in the folder it runs from, then in its parents, and stops at the Godot
project root. gdtest reads the same file whether it is started by
`gdsuite test`, from a terminal, or from the editor panel.

**Keep gdtest's settings in one file.** When `gdsuite.toml` has a `[test]`
section, a `gdtest.toml` next to it is ignored, with a warning: the two files
are not merged.

Priority order: **CLI flag > env var > config file > built-in default**

## gdtest.toml

For `godot_exe`, the built-in default is now auto-discovery of a compatible Godot 4 binary from common command names and common install locations.

```toml
# gdtest.toml — all fields are optional

harness    = "addons/gdtest/gdtest_worker.gd"  # path to gdtest_worker.gd
jobs       = 4          # parallel workers (default: CPU count)
reporter   = "pretty"   # "pretty" | "tap" | "junit"
isolation  = "file"     # "file" | "test"
timeout    = 5000       # per-test timeout in ms
timeout_warn = 2000     # slow-test warning threshold in ms (no kill)
fail_fast  = false      # stop after first failure
retries    = 0          # re-run failing tests up to N extra times
include    = ["test/**/*.gd", "**/*.test.gd"]  # discovery globs (these are the defaults)
exclude    = ["test/manual/**"]  # discovery excludes for directory/default scans
```

`exclude` is for your own folders. Hidden folders (`.godot`, `.git`…),
`addons`, folders with a `.gdignore`, and nested Godot projects are always
skipped when walking, so they need no entry.

## Profiles

Profiles overlay the base config — useful for CI vs local settings:

```toml
# gdtest.toml
harness = "addons/gdtest/gdtest_worker.gd"

[profile.ci]
reporter  = "junit"
fail_fast = true
jobs      = 4
timeout   = 10000
```

Activate with `--profile`:

```sh
gdtest test/ --profile ci
```

## Environment variables

Every setting has a corresponding env var that can substitute for a CLI flag:

| Env var | CLI flag |
|---|---|
| `GODOT_EXE` | `--godot-exe` |
| `GDTEST_HARNESS` | `--harness` |
| `GDTEST_JOBS` | `-j` |
| `GDTEST_REPORTER` | `--reporter` |
| `GDTEST_ISOLATION` | `--isolation` |
| `GDTEST_TIMEOUT` | `--timeout` |
| `GDTEST_TIMEOUT_WARN` | `--timeout-warn` |
| `GDTEST_FAIL_FAST` | `--fail-fast` |
| `GDTEST_RETRIES` | `--retries` |
| `GDTEST_UPDATE_SNAPSHOTS` | `--update-snapshots` |

## CI example (GitHub Actions)

```yaml
- name: Run gdtest
  run: gdtest test/ --profile ci --no-auto-import
```

JUnit XML integrates with GitHub's test reporter when piped to a file.

## In gdsuite.toml

Every key above goes under `[test]`, and profiles under `[test.profile.<name>]`:

```toml
# gdsuite.toml
[test]
harness = "addons/gdtest/gdtest_worker.gd"
exclude = ["test/helpers/**", "test/mocks/**"]

[test.profile.ci]
reporter = "junit"
fail_fast = true
```
